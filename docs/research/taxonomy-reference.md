# 分类参考的组织方式

更新：2026-10-31。

这份目录解决“每一级有哪些类别、各自做什么、可以看哪些游戏”的阅读问题。范围是本库当前收录的 122 项机制，不宣称穷尽所有游戏机制，也不把编辑分组称为行业标准。

## 三层机制目录

机制按“维度 → 分组 → 原子机制”浏览，具体游戏实例作为证据入口。九个维度仍使用原来的 ID、名称和判定口径；本次没有移动机制的主维度，也没有修改机制名称或定义。

|一级维度|二级分组|原子机制数|
|---|---|---:|
|核心交互|移动与攀越；特殊位移与空间连接；攻击与招架操作；物件排列与放置；物理操纵与环境改造；节奏与持续输入|17|
|规则与结算|完成条件与计分；生命、姿态与状态；效果组合与规则改写；位置收益与区域规则；胜负比较与赌注；检定与集体裁决；自动执行结算|17|
|时间与流程|回合顺序与阶段；时钟推进与决策窗口；路径选择与继续流程；重试、复活与世界循环；昼夜、天气与季节|13|
|构筑与配置|装备选择与空间配置；技能路线与模块组合；局内卡组发展；招募与队伍配置；遭遇布置；配置保存与复制|11|
|成长与延续|跨局保留与永久损失；经验积累与技术发展；目标、知识与能力门槛；任务与关系发展；持久收集记录|11|
|资源与经济|采集与战斗供给；稀缺、需求与容量；配方与生产链；生产与设施投资；运输与供给网络；温度管理；交易与市场分配；收益归属与共同余额|21|
|信息与认知|未来行动与对象预览；隐藏信息与可见权限；线索推理与规则发现；线索记录与空间导航；感知、潜行与追踪|15|
|参与者关系|合作与共同目标；竞争与外交关系；角色职责差异；同步与异步参与|7|
|变化与随机|随机取样与候选供给；布局生成与遭遇变化；随机过程重现；世界模拟与事件调度|10|

共 50 个分组，每项机制只出现于一个二级分组。分组数量没有按维度平均分配，也没有为了合并目录而合并机制。例如，自动战斗、温度调节和种子重现各自保留清晰的查阅入口。

每个维度解释它回答的问题、使用场景与边界；每个分组解释覆盖内容、设计作用、容易混淆的边界，并列出具有已有证据的游戏切面。分组中的机制并不必然同时存在于每款示例游戏。

## 类型、配方与标签的位置

32 种复合类型仍是与机制目录并列的入口。即时战略、卡组构筑、类银河恶魔城等词通常横跨几个维度，不能当作原子机制的上位节点。类型中的必要、常见、可选组成服务本库的比较与讨论，不构成排他的市场分类。

组合配方组织的是设计假设：哪些机制承担什么职责、可能如何协同、可能在哪里冲突、原型应验证什么。它也不属于机制目录的下一层。配方参考游戏不能被解释为已核验具备全部组件。

题材、视角、平台属于辅助描述。它们能帮助找作品，但不直接证明一条规则存在；本次没有扩成新的原子维度，也没有为游戏补填未经核验的标签。

## 示例与来源

分类组织沿用已有 [`game-evidence.json`](game-evidence.json) 与 [`source-verification.json`](source-verification.json) 的来源和观察；补证阶段另为能力检定增加一条实例与两项官方来源。既有公开资源复用结论见 [`taxonomy-notes.md`](taxonomy-notes.md)：保留项目自己的九维与实例状态模型，少量扩展导航数据，不导入外部分类词表或第三方游戏断言。

示例只选 `present` 或 `conditional` 实例，保留实例 ID、具体范围、来源、依据类型与条件。展示说明直接使用对应实例的 `rationale`，没有把模式事实扩大为整款游戏的事实。典型示例是供比较的切面，不是人气排名、行业代表性排名或试玩结论。

当前 121 项机制至少有一个这样的实例。《极乐迪斯科》的[官方主动检定开发日志](https://discoelysium.com/devblog/2016/10/06/active-skill-checks)说明角色能力与任务难度相比较、掷骰参与结果；[发行后官方 FAQ](https://steamcommunity.com/app/632470/discussions/0/3175526477766541689/)确认白色检定与技能提高后的再尝试。这两项资料共同支持基础主流程的能力检定实例，不据开发期文章保证现行版本的所有数值与例外。

`next-piece-preview`（后续对象预览）仍缺本库游戏范围内的已核验实例。已查到的明确官方介绍属于 Tetris Effect: Connected 等独立作品，不能当作现有 Tetris 基础规则档案的证据；Tetris.com 当前网页重定向后的可读正文未给出预览规则。本轮保留缺口，没有为凑齐覆盖增加独立游戏或套用其他版本。缺实例不等于游戏没有该机制。

分组与示例代码见 [`taxonomy-reference.ts`](../../src/data/taxonomy-reference.ts)。完整性测试检查：九维不变、122 项覆盖且不重复、分组与主维度一致、典型示例属于该分组、原实例与范围/来源/条件一致，以及证据缺口不被自动填充。测试只证明导航与现有资料一致，不代替来源事实核验。
