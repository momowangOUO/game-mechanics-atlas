# 静态发布与资料扩充

本轮按用户确认的计划执行：现有源码仓库保持私有，完成静态网站后尝试公开发布 GitHub Pages；资料以广覆盖为先，并制作全量独立插画。

## 交付目标

- 80 款游戏、至少 120 个原子机制、32 个复合类型、32 组配方、120 条机制关系。
- 至少 600 条有依据的机制实例、120 个独立来源页面。未知、重复范围和没有证据的否定不能用于凑数。
- 用户后续调整：游戏条目优先直接获取官方代表图，不再逐款生成插画；保留来源与权利归属。22 张新增配方图继续原创，沿用既有正式素材与画风。
- 根路径与项目子目录均能纯静态运行，保留搜索、图谱、实验室、对比和本地数据导入。
- 通过静态构建和真实浏览器验收，再启用 Pages。若账号资格或权限不支持，保留完整产物并明确阻塞，不改变源码可见性。

## 当前执行

- 静态导出、查询参数和发布工作流已实现，最终项目路径 42 项浏览器回归通过。
- 数据规范化与扩充已实现，内容门槛校验零错误，独立抽审的已知重要问题已关闭。
- 80 张官方游戏代表图和 32 张配方图已接入，134 项正式资源服务摘要一致。
- 总图、案例局部关系图、类型与来源检索分页，以及紧凑手机的参照分区已通过回归。
- GitHub Pages 创建请求实际返回 422，当前套餐不支持此私有仓库；仓库不改公开，不另外购买或建公开仓库。

完整规模、验证和未上线原因见[本轮验收](verification.md)。源码推送与最终远端检查继续由交付步骤完成。
