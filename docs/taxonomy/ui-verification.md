# 分类图鉴界面验证

2026-10-31。此记录对应开发服务上的界面检查；最终静态构建与全站回归由集成验证补充。

## 本次实现

`/taxonomy` 按九维 → 50 个编辑分组 → 122 条原子机制浏览。每层可读用途和边界，分组与机制提供有来源的游戏实例入口。机制阅读卡将定义、设计作用、风险、纳入条件、排除边界以及条件实例分段分页。分组没有修改机制的规范 ID 或主维度。

桌面并排显示维度、分组与机制；阅读机制时替换右侧内容。手机逐层进入并保留选择，按视口高度调整每页条数。搜索覆盖分类说明、机制定义与条件、设计作用和已记录的游戏观察。分类说明将复合类型、配方与题材等元数据另作解释。

机制档案保留原筛选，新增图鉴入口与分组路径。游戏链接带明确 `scope`，游戏详情校验范围属于当前游戏后选择对应记录；重复参数或其他游戏的范围回到默认范围。

## 已完成的检查

- `tests/e2e/taxonomy.spec.ts` 原有五项定向测试全部通过，覆盖层级探索、搜索空状态、手机返回、机制路径、长条件实例与范围链接。追加的末尾五项机制检查也通过，六项均使用真实 Playwright 点击。
- 在 320×640 模拟视口下，对全部 50 个分组的用途、典型游戏与边界页签作布局检查，未发现面板溢出。结果见 [group-layout-audit.json](group-layout-audit.json)。
- 已实际查看 1440×1050、390×844、320×640 的原始截图。两种手机视口无整页纵向滚动与横向溢出，主要操作位于底部导航之上。
- 本轮组件类型检查曾通过；最终生产编译由集成验证确认。

长批次开发态机制检查在末尾出现分页状态错位和级联超时，因此不将该次运行称为 122 项全部通过。独立重新打开末尾五条机制后，所有页签与分页可正常点击、文本无溢出。批量脚本已改为逐次加载页面并等待页码提交，待最终静态服务运行完整检查。
