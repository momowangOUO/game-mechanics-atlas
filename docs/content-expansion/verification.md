# 案例扩充与画风修正验收

日期：2026-11-02。环境：Windows、Node.js 24.11.1、Next.js 16.4.3、Playwright 无头 Microsoft Edge。手机检查使用模拟视口，不代表真机或全部浏览器覆盖。

## 数据与构建

- 类型检查与生产构建中的 TypeScript 检查通过。
- Vitest：20 个文件、115 项测试通过。
- `check-content.mjs`：459 款游戏、127 条机制、3196 条机制记录、974 个不重复来源 URL，零错误；每款游戏至少六条带来源的正向记录。
- `check:coverage`：131 款手机发行、97 款手机原生或先发、114 款经典游戏；46 个类型及全部 21 个玩法方向至少十款。语言解谜四款的资料缺口保留，未填入证据不足的候选。
- 组合覆盖：358 个组合有案例，25 个空缺留有有限范围的检索记录，604 个待补查。兄弟模式不能互相借用分类，明确的父子范围只在更具体的范围内匹配。
- Agent 导出：7 项通过；保留机制状态、条件、范围、来源和编辑判断，新增玩法方向及组合覆盖，不导出合成需求。
- Windows 文件兼容 24 项、静态预览 2 项、搜索采集解析 3 项通过。
- `npm run build:pages` 通过，732 个构建页面任务完成；729 条正式内容路径进入 sitemap。构建并发限制到最多四个进程，最终构建没有出现页生成超时重试。

## 浏览器与实际画面

完整 127 项本机回归首次结果为 120 项通过、7 项失败：六项仍从旧数据文件读取固定数量，一项在选中机制跳转后检查了未进入视口的懒加载图片。修正为运行时完整目录和实际滚动到图片后，相关 17 项回归全部通过。

首轮远端 Chromium 回归 126 项通过，一项搜索导入测试因数据入口迁移后漏改变量名而报错。该测试已改用完整类型注册表，实际单项回放通过；此次修正只涉及测试和本验收记录。

另外检查截图发现，新组合结果继承了旧的手机横向卡片样式，卡片被压成窄列。组合页和玩法方向详情已改为纵向网格；新增回归断言卡片实际宽度与上下顺序，320／390 像素通过。没有仅凭“整页不溢出”判断内容可读。

已实际查看 [390 像素对话图解](runtime/dialogue-390.png)、[桌面消除充能图解](runtime/charging-1440.png)、[手机组合结果](runtime/coverage-390.png)、[桌面组合结果](runtime/coverage-1440.png)及游戏代表图。8 个页面与视口检查均无页面错误、无文档横向溢出，见[运行记录](runtime/report.json)。

新图逐项对照旧的“跳跃”“直接移动”和 Q 版 RIN：采用重画后的粗描边、Q 版人物、分块阴影和暖色石木场景。匹配消除第二格修正为三颗紫色宝石已连成一行。旧 122 组图像保持原文件。
