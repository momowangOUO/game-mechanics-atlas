# 分类参考与真实搜索数据修订

本轮依据：用户要求停止用虚构数据展示热门类别；主要用途是逐层了解有哪些类别、各自在做什么，以及典型游戏的具体用法。

## 实现安排

1. 分类参考成为首页、章节和导航的主要入口。用固定九维 → 编辑分组 → 原子机制 → 游戏中有范围的实例组织查阅，保留复合类型、配方与元数据的独立身份。
2. 分组完整覆盖现有原子机制。每组说明负责的问题、设计作用和边界；实例引用已收录的范围、状态与来源。未收录证据时明确说明，不从类型标签补全机制。
3. 复合类型页增加具体玩法流程、与相近类型的差别，以及带机制说明的游戏参照。
4. 移除合成搜索数据的默认排名。真实公开榜单保留原始指标、地区、时间和来源，不将增幅名次或相对指数改写成搜索人数、次数或类别需求。
5. 当前类别需求无法采集时显示未取得。没有可比需求和充分供给时，不计算蓝海、红海结论。
6. 验证分类覆盖及实例引用、真实数据口径、静态构建、分层导航、检索、手机布局和旧工具流程；修改保存在原私有仓库。

复用现有 Next 静态导出、知识实体与官方素材，不新建后台或定时采集服务。保持已确认的研究室、黑发女仆、粗线条与纸面界面。

## 当前已知限制

Google Trends 同组类别请求实际返回 HTTP 429。Google 官方年度游戏趋势榜可读取，但其增长名次不能代表当前类别搜索总量。两者须在界面上分别呈现。
