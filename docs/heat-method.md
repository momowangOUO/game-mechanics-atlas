# 搜索关注与供给分析口径

当前本地分析器已在 `src/lib/heat.ts` 实现，`validateSearchImport()` 校验输入，`analyzeHeat()` 计算需求、收录供给、指数和趋势。以下指数是本平台的研究启发式，不是市场公认标准、销量预测或投资结论。随应用交付的全部搜索种子均为合成示例；用户导入记录保留原有来源类别，混合数据明确披露合成成分。当前没有真实日志采集、自动研究或远程分析服务。

## 需求是什么

`demand` 是选定期间归属于某个主题的搜索事件次数。它不是独立玩家人数，也不等于购买意愿。网站未来的真实站内日志只代表本站用户；第三方搜索数据的地区、平台与采样范围必须另外记录。

当前 `SearchQueryStat` 按日记录唯一ID、数据集ID、来源、`date`、地区、语言、搜索词、事件数、主题归因和归因方式；分析器据此选取日期区间。记录不包含账号、IP或设备指纹。重复记录ID导致整批导入被拒绝；有效导入整体替换本标签页内存中的工作记录，不悄悄累加。

搜索词先做空白、大小写和已审定别名归一。歧义词进入“未归类”池，不按最相似字符串强行归类。`lol` 对应游戏搜索，再归因到某类方向，是代理信号；直接搜索“MOBA”则是直接信号。两者在展示时可分开查看，不把代理归因写成玩家明确表达的机制偏好。

同一事件可在游戏、类型、机制、组合等不同观察维度各贡献最多1份权重，但同一维度内的归因权重合计不能超过1。全站搜索总量直接累加原始事件，不能累加不同维度的主题计数，否则会重复计算。一个机制可关联多个类型，但机制的主分类维度不随这些关联变化。

类型父级按唯一事件归因求和，不能先平均各子类再把平均值当成总关注。例如，某方向1000万次搜索，另一个方向的10个子类各1万次，后者合计是10万次，前者总量仍为其100倍。子类数和收录游戏数都不能改变这个关系。

## 供给是什么

`supply` 是已收录样本中，有足够证据符合主题条件的不同游戏数量。同一游戏的多个模式、版本或机制实例不重复算作多个竞品。MVP没有全市场完整清单，因此页面必须使用“收录样本供给”，不能只写“市场上共有”。

组合供给要求所需机制在同一有效范围中共同存在。不能把游戏甲的主模式机制、DLC机制、某角色专属机制跨范围拼成一个已经成立的组合。

- `present` 可计入对应范围的已确认供给。
- `conditional` 单列“条件匹配”，并说明条件；不自动当成无条件供给。
- `absent` 只在已核验的范围生效。
- `not_applicable` 表示该范围无适用对象，不代表整个游戏永远不支持该机制。
- `unknown` 和未记录实例均进入未知范围，不能当作不存在。

每个主题同时保留已确认数、条件匹配数、未知范围数和样本总数；已确认数是已发现供给的下界。已确认数为0时显示“尚无足够样本”，不能直接包装成最高蓝海机会。

## 初版公式

同一个时间区间、数据来源、地区和主题种类组成比较组。游戏、传统类型、原子机制和组合分别计算基准；原始次数保持可见。界面的普通文本筛选不重新计算比较组基准，避免同一主题因搜索框筛选而分数漂移。

令：

- `D`：该主题的归因搜索次数。
- `Dmax`：完整比较组内最大搜索次数。
- `S`：符合条件的已确认样本游戏数。
- `k = 2`：供给平滑参数，相当于要求零到少量样本之间不要出现无穷比值。
- `d = sqrt(D / Dmax)`：需求尺度，范围0–1。开方保留排序与总量关系，同时让小方向在图中仍可辨认。
- `c = S / (S + k)`：供给拥挤系数，范围0–1。

计算：

```text
需求指数 = 100 × d
蓝海线索分 = 100 × d × (1 − c)
红海线索分 = 100 × c × (1 − 0.5 × d)
```

蓝海分强调需求规模与较低已发现供给。红海分强调供给拥挤、需求未能同比支撑竞争；高需求也不能将拥挤度完全抵消。这两个分数不是互补概率，不能相加后解释为100%。

原始搜索次数决定热门排行；蓝海或红海分不能取代热度排行。供给量的增加永远不会让搜索热度增加。在其他输入固定时，增加供给应使蓝海分不升、红海分不降。

`Dmax=0` 时整组没有可用的相对需求基准，分数为 `null`；这不改变 `measurementStatus`：已记录的零值仍显示0，未记录才显示“未采集”。`D=0` 的主题不进入蓝海机会排行。`S=0` 的主题保留需求与未知状态，可显示研究线索，但不进入正式蓝海榜；它需要补充竞品检索。条件匹配和未知范围仍必须显示，不能用平滑项掩盖资料缺口。

分数最多显示整数或一位小数，不宣称具有相应统计精度。调整 `k` 必须在方法说明和导出结果中保留参数版本。

## 纯演示算例

下面是虚构方向，不是对任何真实游戏类别的市场判断。三者使用同一比较组，`Dmax=1000万`、`k=2`。

|方向|搜索次数|已确认样本供给|蓝海线索分|红海线索分|
|---|---:|---:|---:|---:|
|甲|1000万|12|14.3|42.9|
|乙|10万|2|5.0|47.5|
|丙|400万|1|42.2|22.8|

甲搜索最多，应排在热门榜首；丙在此假设样本中更适合继续研究；乙的需求相对弱、供给压力相对高。丙只有1个已确认样本，结果仍须醒目标记“样本有限”，不能写成“已证明的市场空白”。

## 趋势与时间序列

等长的当前与上一期间按同一主题归因规则比较：`trend=(current-previous)/previous`。需要按数据日期选择完整记录；不能把一个月的次数作为一天的次数重复累加。不同长度区间应先转为日均值，并说明口径。

上一期为0、当期大于0时标记“新出现”，不显示无穷百分比；两期都为0时显示“无变化”；缺失上一期时显示“暂无可比数据”。合成时间序列中的增长只是演示，不得写成当前真实行业趋势。

## 导入和未来替换

搜索事件聚合与指数计算分为两层，前者产生规范主题计数，后者只消费计数及供给。当前页面已支持本地JSON文本和文件导入；API或第三方分析服务接入是后续扩展，MVP不含自动采集或定时研究。

导入必须核对：schema版本、重复ID、非负有限整数次数、合法日期与区间、已知主题、归因权重、相同口径、来源类别。错误记录给出具体位置；不能先部分覆盖有效数据再报错。种子、导入与未来日志分别显示来源，不合并后隐藏合成数据。

## 当前实现的核验要点

1. 1000万与10组各1万的需求总量按100倍保留，排行不受供给量干扰。
2. 别名不重复产生记录；跨观察维度的总量不重复加计。
3. 组合供给按游戏去重，且要求同范围共同存在。
4. 未知和条件匹配不转为确定不存在或无条件存在。
5. 全零需求、零供给、极大次数、负数、非有限值和重复导入有明确行为。
6. 供给增加使蓝海分不升、红海分不降；正数需求增加使热门排名不降。
7. 趋势对缺失期和零基数给出状态，而非无穷或伪造0%。
8. 所有演示图、榜单、导出和结论保留合成数据标记与收录样本口径。
