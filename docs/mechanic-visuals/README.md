# 机制图标与漫画

122 项机制各有一张独立图标、一组三格插画、三格网页文字和可切换的规则示意图。图标与漫画通过内置图像模型生成，正式素材分别位于 `public/art/mechanics/` 和 `public/art/comics/`。图标为 256 × 256 透明 WebP，漫画为 1800 × 600 WebP，每格等宽。

## 角色与画法

沿用黑长发、紫色蝴蝶结、黑白女仆装、粗描边和赛璐璐画法。Q 版看板娘负责讲解；冒险者、棋子、卡牌或机器是示意对象，不把看板娘写成玩家操控的角色。被指出有额外手臂的旧角色图已替换，正式入口为 `public/art/chibi-guide.webp`。

先完成直接移动、跳跃、撤离兑现三组样例，再制作其余 119 组。实际生成提示词记录在 `comic-sample-prompts.json`、`comic-prompts.json` 和 `icon-prompts.json`；最后一份记录覆盖后续批次的 119 个图标。生成记录中的场景说明不直接用作网页文案。

## 文字与规则

网页使用 `src/data/mechanic-scenes.ts` 的 366 格说明和 366 个标签。三格依次交代情境、关键操作和结果，不把同一条规则换三种说法。文字在 HTML 中渲染，方便修改、选取与机器读取，避免依赖图片内的生成文字。

规则图按操作、资源、时间、构筑、信息等具体机制分别绘制，位于 `src/components/diagrams/`。漫画使用原创情境帮助理解规则，游戏范例复用正式实例、模式、成立条件和来源；不把插画当成游戏实录。

## 检查记录

- 实际逐张查看 122 个图标，以及包含全部 122 组三格漫画的 31 张联系表，检查轮廓、人物肢体、裁切、示意对象与机制含义。未发现需要重做的明显多肢体问题；这不等同于用户已认可每一张插画。
- 浏览器检查直接移动、跳跃、撤离兑现的桌面三格与手机逐格切换，并检查预览机制的具体游戏版本范围。
- 自动检查覆盖全部 244 张机制素材的请求、WebP 格式、图解完整性和各机制 ID 的对应关系。
- 实际界面截图保存在 `runtime/`；测试与发布结果见本轮验收记录。

插画按页面延迟加载；目录与图谱只使用小图标，不一次性下载所有漫画。
