# Game Mechanics Atlas Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Execute the tasks below against the existing product specification; maintain this checklist.

**Goal:** 先制作六类高保真样张，再交付可运行、经验证并上传私有GitHub仓库的游戏机制研究网站。

**Architecture:** Next.js App Router + TypeScript，本地可版本控制数据与Zod验证；知识查询、搜索归因/供给分析、规则实验室分别使用纯函数。页面只引用规范机制身份，复合类型与原子机制分开。图谱使用XYFlow，动效使用Motion。

**Tech Stack:** Next.js 16.4.3、React、TypeScript、Motion、XYFlow、Zod、Vitest、Playwright；实际安装版本由lockfile固定。

**Spec:** `docs/spec.md`、`docs/data-contract.md`、`docs/heat-method.md`、`.design-scout/design-direction.md`。

## Global Constraints

- 用户已在聊天中选择“凉宫春日：清晰赛璐璐”，以此制作原创黑发女仆。不要使用未采用的现代霓虹女仆。
- 必须先保存六类高保真HTML/CSS样张及实际PNG，再正式建立应用。聊天已有连续执行授权，不额外等待一次许可。
- 固定九维、五状态、明确作用范围；未知不转为不存在，组合不跨范围拼接。
- 真实事实与编辑判断分开，所有搜索种子明确合成；供给不是热度。
- 不修改父分享项目，不实现自动研究、定时更新或抓取平台，只推送新建私有仓库。

## Review Focus

- 零需求/零供给/重复归因/无上一期数据必须有明确状态，不生成无穷或伪造增长。
- 机制在不同页面、图谱和实例中必须查回同一主维度，组合只在有效共同范围内匹配。
- 手机切换、空结果、失效路由、导入错误、键盘关闭弹窗与减弱动态实际验证。
- 游戏资料是基于已核验来源的稀疏实例，不以补全矩阵的方式编造事实。
- 最终页面与样张比较角色比例、字阶、边框、布局和色彩，不只验证路由成功。
